# Scribloom 処理フローとデータの流れ

このドキュメントでは、Scribloom の内部処理と主要なデータの流れを整理します。ユーザーが「執筆→保存→閲覧」するまでの一連のステップを明示し、設計意図を補足します。

---

## 🗂️ フロー概要図

```
[ユーザー操作]
     ↓
[generate_daily_prompt()] ←── UI 起動時に呼び出し
     ↓
[表示されるテーマ / ジャンル / 舞台]
     ↓
[執筆（Markdown 入力）]
     ↓
[保存ボタン押下]
     ↓
[Post モデル生成]
     ↓
[JSON 形式で保存（date をキー）]
     ↓
[load_posts() により履歴取得]
     ↓
[履歴タブで展開表示]
```

---

## 🎯 処理フロー詳細

### 1. お題生成

- `generate_daily_prompt()` により日付ベースの固定シードを生成
- テーマ・ジャンル・舞台を疑似乱数で決定（同じ日なら同じお題）
- フロントエンド起動時に自動呼び出し

### 2. 投稿作成

- ユーザーが Markdown 形式で文章を入力
- 文字数カウントをリアルタイムで表示
- Markdownプレビューを展開可能

### 3. 投稿保存

- ボタン操作で保存を明示
- `Prompt` + `Post` モデルを Pydantic で構築
- `save_post()` により JSON ファイルへ追記
- `posts.json` に `{date: {...}}` 形式で格納

### 4. 履歴表示

- `load_posts()` により全投稿を読み込み
- 日付降順にソートしてタブに展開
- プロンプト内容と文字数を見出しに含める

---

## 🧠 使用される主なデータ構造

### Prompt
```python
Prompt(theme: str, genre: str, setting: str)
```

### Post
```python
Post(date: date, prompt: Prompt, content: str, word_count: int)
```

---

## 📦 永続化形式

保存される `data/posts.json` の構造例：

```json
{
  "2025-07-11": {
    "prompt": {
      "theme": "記憶",
      "genre": "SF",
      "setting": "宇宙船の中"
    },
    "content": "彼は目を覚ましたとき、すべてを忘れていた。",
    "word_count": 22
  }
}
```

## 🧪 テストとの関連

- `test_prompt.py`: お題生成が日付ベースで再現性を持つか検証
- `test_storage.py`: 投稿の保存・読み込みの正常性と例外処理を確認

## 🎯 今後の拡張に備えて

- お題生成を選択式に変更した場合はフロー分岐が必要
- GPTなど外部APIを利用した投稿支援機能は、フロー中に「ヒント生成」などを挿入予定
- クラウド保存に切り替える際は `storage.py` を抽象化して切り替え可能にする予定
