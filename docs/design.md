# Scribloom 設計思想と技術選定

このドキュメントでは、Scribloom を設計する上で重視したユーザー体験、技術的判断、そして今後の展望について説明します。

---

## 🎯 プロジェクトの目的

Scribloom は「書くきっかけと場」を提供するための創作支援ツールです。  
日替わりのお題によって創作意欲を刺激し、書いた内容を履歴として蓄積・振り返ることで、書く習慣と自己表現の継続を促します。

---

## 🧭 ユーザー体験の設計方針

- **画面は静かに、選択は少なく**  
  書くことに集中できるように、余計な設定を排除し、ミニマルな UI を構成しました。

- **保存と履歴は自然な流れでつながる**  
  書いた投稿はワンクリックで保存され、すぐに履歴として確認可能。創作の記録が途切れないように設計されています。

- **テーマ提示 → 執筆 →振り返り**  
  毎日の体験がループすることで、ユーザーが自分の変化に気づけるような構造を目指しています。

---

## 🧪 技術選定の背景

| 技術         | 採用理由                                                                 |
|--------------|--------------------------------------------------------------------------|
| **Streamlit**| UI 実装の高速化と Markdown プレビューの柔軟な表現のため                     |
| **Pydantic** | 投稿データの構造とバリデーションを型安全に管理するため                       |
| **JSON 保存**| 最も軽量かつローカル環境で管理しやすく、履歴が見える形で残るため             |
| **pytest**   | ロジックや保存処理の正しさを検証し、今後の改修に安心感を与えるため           |

---

## 📝 お題生成ロジックの意図

- **日付ベースで変化するお題**  
  曜日や季節に合わせて自然に変わっていく仕組みを意図。ユーザーが「今日はどんなテーマかな？」と期待できる構造を設計。

- **同じ日に開けば同じお題**  
  突然変わるのではなく、1日単位で固定することで創作環境の安定感を提供。

- **ジャンル＋舞台付き**  
  テーマだけではなく、設定と世界観の足がかりを組み合わせることで、空想の広がりを支援。

---

## 🚫 除外した要素（MVP外）

以下の要素は初期バージョンでは意図的に除外し、今後の拡張として余白を残しました：

- ユーザーアカウント / ログイン機能  
- 投稿の共有や公開フィード  
- GPT との執筆支援連携  
- お題のカスタム選択や再生成

これらは「まず自分だけの創作に向き合う場」が成立した上で追加することで、シンプルさと目的意識を保っています。
